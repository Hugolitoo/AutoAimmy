# Local learning backend

The application captures candidates locally, offers human review, splits complete recording sessions into training and validation sets, and measures detector results at IoU 0.5. Predictions are proposals, never ground truth. Reviewed empty images are valid negatives. Exact duplicate images are stored once. Capture storage stops at 2,000 images or 512 MiB.

`ModelLearningCoordinator.OptimizeConfidence` selects a confidence threshold using training frames, then accepts it only if F1 improves by at least 0.01 on held-out sessions without a precision/recall regression above 0.01. This changes configuration; it does not train model weights. The prediction filter matches Aimmy's square input and local runtime class-wise NMS (IoU > 0.45, the top 1,000 candidates and at most 100 kept boxes). CPU evaluation timing includes image load and preprocessing, so it is not a gameplay FPS measurement.

`OnnxLearningDetector` runs actual ONNX inference. `EvaluateAndPromote` compares both models, checks the same accuracy gates and a latency gate, saves immutable model copies and a rollback pointer. It never overwrites the supplied model. Model selection takes effect through `ResolveSelectedModel`; a running session should switch only at a safe boundary. Class order must remain identical, not just class count.

`runner.py` provides offline recovery and training. It never installs packages or downloads weights. Use `--mode inspect` to get machine-readable missing prerequisites. Training requires `--trusted-local-weights`, an existing reviewed dataset, and a new output directory. The runner disables networking before importing training packages, disables cloud logging and automatic package installation, validates label/image hashes, exports a candidate ONNX and leaves promotion to the application's independent evaluator. The reserved validation sessions are not supplied to the training loop, including its internal best-checkpoint selection. Training metrics are not promotion evidence. Only the application's later ONNX comparison uses the independent validation split.

`--mode recover --onnx <path> --output <new-directory>` reconstructs supported classic YOLOv8 detection exports from numeric ONNX tensors. It matches a built-in architecture, verifies convolution names and shapes, restores fused weights and compares two actual CPU forward passes against ONNX Runtime. External tensors, unsupported layouts and non-equivalent outputs are rejected. Accepted output is owned `recovered.pt` with hash and provenance, not an arbitrary checkpoint discovered on disk. Reconstruction preserves inference behavior within the checked tolerances; it is not training or evidence of improved detection.

`TrainingJobCoordinator` integrates the runner with application state and cancellation. The shipped layout is `local-learning/runner.py` plus `recover_onnx.py`. `TrainingRuntimeSetup` can install a hash-verified portable Python/PyTorch CPU environment at `data/learning/runtime/python.exe` from the packaged GitHub manifest (approximately 284 MiB, one download). A compatible local Python on PATH is also discoverable; Windows Store aliases are ignored. The app downloads the environment separately from the network-blocked worker.

If source trust is absent, the worker tries validated ONNX reconstruction. Alternatively, the user can call `RegisterTrustedSource` to bind explicitly selected source weights to the ONNX hash. A changed source loses trust. After an accepted training result, validated output `.pt` weights are bound to the promoted ONNX automatically so another cycle can run. Importing external `.pt` files remains a trust decision because PyTorch checkpoints can contain executable pickle data; never register arbitrary discovered files automatically.

The automatic workflow requires at least 40 human-reviewed frames across two complete sessions, with at least 20 frames in each split and 20 validation targets. Related promoted model hashes can reuse labels only with matching class semantics. The worker trains for ten CPU epochs, exports, evaluates independently and only promotes an accepted candidate. Training is cancelled when R6 returns to the foreground; partial epoch progress is not guaranteed to resume. A rejected confidence attempt is recorded separately and cannot overwrite the last accepted recommendation. Later fresh reviewed validation captures can trigger rollback if the active model regresses against its predecessor.

An actual reconstruction, one-epoch training and ONNX export were tested locally on synthetic integration data. Independent evaluation rejected that synthetic candidate for insufficient improvement. This is an end-to-end implementation check, not evidence of better R6 performance. Human label review remains necessary; repeated model agreement or probable visual impact cues do not prove complete enemy annotations.

Reference contracts: [Ultralytics training](https://docs.ultralytics.com/modes/train/), [Python API](https://docs.ultralytics.com/usage/python/), [ONNX export](https://docs.ultralytics.com/modes/export/).
