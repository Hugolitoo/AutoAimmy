# Local learning backend

The application captures candidates locally, offers human review, splits complete recording sessions into training and validation sets, and measures detector results at IoU 0.5. Predictions are proposals, never ground truth. Reviewed empty images are valid negatives. Exact duplicate images are stored once. Capture storage stops at 2,000 images or 512 MiB.

`ModelLearningCoordinator.OptimizeConfidence` selects a confidence threshold using training frames, then accepts it only if F1 improves by at least 0.01 on held-out sessions without a precision/recall regression above 0.01. This changes configuration; it does not train model weights. The prediction filter matches Aimmy's square input and local runtime class-wise NMS (IoU > 0.45, the top 1,000 candidates and at most 100 kept boxes). CPU evaluation timing includes image load and preprocessing, so it is not a gameplay FPS measurement.

`OnnxLearningDetector` runs actual ONNX inference. `EvaluateAndPromote` compares both models, checks the same accuracy gates and a latency gate, saves immutable model copies and a rollback pointer. It never overwrites the supplied model. Model selection takes effect through `ResolveSelectedModel`; a running session should switch only at a safe boundary. Class order must remain identical, not just class count.

Optional `runner.py` is an offline training path for locally supplied, explicitly trusted PyTorch `.pt` weights. It never installs packages or downloads weights. Use `--mode inspect` to get machine-readable missing prerequisites. Training requires `--trusted-local-weights`, an existing reviewed dataset, and a new output directory. The runner disables networking before importing training packages, disables cloud logging, validates label/image hashes, exports a candidate ONNX and leaves promotion to the application's independent evaluator. The reserved validation sessions are not supplied to the training loop, including its internal best-checkpoint selection. Training metrics are not promotion evidence. Only the application's later ONNX comparison uses the independent validation split.

This checkout currently contains inference ONNX models, no corresponding `.pt` source weights and no PyTorch/Ultralytics training environment. No model has therefore been retrained. An ONNX-only model is usable for local evaluation and threshold optimization. Reliable label correction still requires review; repeated model agreement cannot prove a target is an enemy.

`TrainingJobCoordinator` integrates that runner with application state and cancellation. The shipped layout is `local-learning/runner.py` next to the application executable. A Python runtime may be provided at `data/learning/runtime/python.exe` or installed on PATH; Windows Store aliases are ignored. Source weights must be selected explicitly through `RegisterTrustedSource`, which binds their hash to the active ONNX model. A changed source loses trust. The worker probes dependencies, builds a reviewed dataset for the exact active model hash, trains locally, evaluates with ONNX Runtime and only promotes an accepted candidate. Missing prerequisites remain explicit `Blocked` states. Importing a `.pt` is a trust decision because PyTorch checkpoints can contain executable pickle data; never register arbitrary discovered files automatically.

Reference contracts: [Ultralytics training](https://docs.ultralytics.com/modes/train/), [Python API](https://docs.ultralytics.com/usage/python/), [ONNX export](https://docs.ultralytics.com/modes/export/).
